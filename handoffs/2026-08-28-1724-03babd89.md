And I took `rc=$?` after a pipe to `head` in my own diagnostic. Both are in `traps.md`. Having the rule written down did not stop me; the gouteur render did, one command later.

The Shortcut build took five rounds and I sent him after the wrong thing in four of them. The error said *"you asked for item 0"* about a field displaying `1`, and it was telling the exact truth — the value had never been stored. I kept reading the message's framing instead of its literal content.

## For Claudes to come

**When a tool's canvas and its data store disagree, the store is the authority — and the tell is an error that names the wrong widget.** Shortcuts reported *"You asked for item 0, but the first item is at index 1"* against an action whose index field displayed `1`. Both were true: the field had never been typed into, so no `WFItemIndex` key existed at all, and the greyed placeholder rendered identically to a real value. Four debugging rounds went elsewhere. The generalisation is not about Shortcuts — **a UI that draws "unset" the same as "set to the default" is an instrument that cannot discriminate**, and the right move is to read what is actually stored (`~/Library/Shortcuts/Shortcuts.sqlite`: workflow in `ZSHORTCUT`, actions as a bplist in `ZSHORTCUTACTIONS.ZDATA`). The same shape appeared twice more the same day: MindNode's Markdown export renders a real tag and literal `#text` identically, so it could never answer "did this become a tag?" — only the snapshot decode could; and MindNode declares `com.taskpaper.text` as a supported document type while refusing the file at runtime. Declared is not honoured, rendered is not measured, and when a cheaper readout conflates two states, the inconvenient instrument is the only one worth trusting.

**Second, on guards:** a signal you have observed *once* is not a signal whose meaning you know. arête gated "is this snapshot current?" on `operation_count == 0`, verified against a map showing 285 pending operations — and within the hour that same map read 0 while its snapshot was still empty, because MindNode prunes operations without rewriting the snapshot. The guard then did precisely what it existed to prevent. A guard is untested until you have watched its signal change.
